# Event Streams & `_NET_ACTIVE_WINDOW` Prior Art for Pergola

## 1. Event Streams to Status Bars

- **i3 (`SUBSCRIBE` IPC):** Clients send a `SUBSCRIBE` message with a JSON array of event names: `workspace` (0), `output` (1), `mode` (2), `window` (3), `barconfig_update` (4), `binding` (5), `shutdown` (6), `tick` (7) ([i3 IPC docs](https://github.com/i3/i3/blob/next/docs/ipc)). Events use the normal IPC framing with the highest bit (`>> 31`) of the 32-bit message type set to `1`, carrying a JSON object with a `"change"` string (plus `"current"`/`"old"` for `workspace`, `"container"` for `window`). Subscribers are tracked in the `all_clients` `TAILQ`; on `EAGAIN`, i3 queues outgoing messages per client and starts a 10-second `ev_timer` (`kill_timeout`), calling `free_ipc_client` if nothing drains within 10s or on write error ([i3 `src/ipc.c`](https://github.com/i3/i3/blob/next/src/ipc.c)).
  - *Failure modes:* Events can interleave before command replies on a shared socket ([i3 IPC docs](https://github.com/i3/i3/blob/next/docs/ipc)); moving containers emits spurious `workspace` (`focus`) events ([i3/i3#3893](https://github.com/i3/i3/issues/3893)); override-redirect popups (e.g. `rofi`) can suppress focus signals ([i3/i3#6640](https://github.com/i3/i3/issues/6640)).

- **bspwm (`subscribe` report):** `bspc subscribe` emits colon-separated items `<type><value>`: `M`/`m` (focused/unfocused monitor), `O`/`o` (occupied desktop), `F`/`f` (free), `U`/`u` (urgent), `L(T|M)` (layout), `T(T|P|F|=|@)` (node state), `G(S?P?L?M?)` (flags) ([bspwm man](https://github.com/baskerville/bspwm/blob/master/doc/bspwm.1.asciidoc)). Subscribers live in a doubly-linked `subscriber_list_t`; `put_status` writes via `vfprintf`/`fflush` and removes on nonzero return or `count == 0`, while `prune_dead_subscribers` probes `write(fd, NULL, 0) == -1` ([bspwm `src/subscribe.c`](https://github.com/baskerville/bspwm/blob/master/src/subscribe.c)).
  - *Failure modes:* Monitors initialize before socket reads, so initial monitor events are missed ([bspwm man](https://github.com/baskerville/bspwm/blob/master/doc/bspwm.1.asciidoc)); swapping desktops across monitors fails to emit `desktop_focus` ([baskerville/bspwm#1166](https://github.com/baskerville/bspwm/issues/1166)); synchronous `fflush` risks stalling the WM on a blocked reader.

- **awesome (signals):** Bars (`awful.widget.taglist`, `tasklist`) run in-process in Lua and bind directly via `connect_signal` / `attached_connect_signal` to `property::selected`, `property::urgent`, `property::active`, `tagged`, `untagged`, and `request::unmanage` ([awesome `taglist.lua`](https://github.com/awesomeWM/awesome/blob/master/lib/awful/widget/taglist.lua)).
  - *Failure modes:* Avoids IPC disconnect/buffer bugs, but suffers from signal storms/redundant layout redraws ([awesomeWM/awesome#2518](https://github.com/awesomeWM/awesome/issues/2518)).

- **xmonad (`logHook` / root property / D-Bus):** `logHook` runs on every internal state update; `DynamicLog` / `StatusBar` formats state to a spawned pipe or writes `_XMONAD_LOG` on the root window (`xmonadPropLog`) for bars to watch ([xmonad `StatusBar.hs`](https://github.com/xmonad/xmonad-contrib/blob/master/XMonad/Hooks/StatusBar.hs), [xmonad `DynamicLog.hs`](https://github.com/xmonad/xmonad-contrib/blob/master/XMonad/Hooks/DynamicLog.hs)). D-Bus status bars rely on external `xmonad-dbus` hooks (exact `xmonad-dbus` failure modes: UNVERIFIED).
  - *Failure modes:* `statusBarGeneric` failed to kill spawned bars on restart/exit, leaving stale processes ([xmonad/xmonad-contrib#668](https://github.com/xmonad/xmonad-contrib/issues/668)); firing `logHook` on every state change floods external readers unless deduplicated.

## 2. `_NET_ACTIVE_WINDOW` Handling

- **i3:** Inspects `data32[0]` (source indication). For pagers (`2`), it unconditionally switches workspace (`workspace_show`) or shows scratchpad (`scratchpad_show`) and forces focus (`focused_id = XCB_NONE`, `con_activate_unblock`). For applications (`!= 2`), it ignores internal workspaces and applies `focus_on_window_activation` (`focus`, `smart`, `urgent`, or `none`) ([i3 `src/handlers.c`](https://github.com/i3/i3/blob/next/src/handlers.c)). `data32[1]` (timestamp) is not checked.
  - *Known bugs:* Applications (`data32[0] != 2`) originally stole focus before `focus_on_window_activation` ([i3/i3#1426](https://github.com/i3/i3/issues/1426)); floating windows were needlessly raised on focus ([i3/i3#2998](https://github.com/i3/i3/pull/2998)); urgent criteria kept matching after activation ([i3/i3#1825](https://github.com/i3/i3/issues/1825)).

- **bspwm:** Ignores `_NET_ACTIVE_WINDOW` when `ignore_ewmh_focus` is set and `data32[0] == XCB_EWMH_CLIENT_SOURCE_TYPE_NORMAL` (1), or when `loc.node == mon->desk->focus`; otherwise calls `focus_node(loc.monitor, loc.desktop, loc.node)`, switching monitor/desktop and focusing. Pending-rule windows postpone the event; unmanaged windows are dropped ([bspwm `src/events.c`](https://github.com/baskerville/bspwm/blob/master/src/events.c)). Timestamp `data32[1]` is not checked.
  - *Known bugs:* Updating `_NET_ACTIVE_WINDOW` before `_NET_CLIENT_LIST` on new windows caused `tint2` to display newly focused windows as inactive ([baskerville/bspwm#911](https://github.com/baskerville/bspwm/issues/911)).

- **awesome:** `ewmh.c` emits `request::activate` with `context = "ewmh"` and `hints = { raise = true }` without checking `data32[0]` (source 1 vs 2) or `data32[1]` (timestamp) ([awesome `ewmh.c`](https://github.com/awesomeWM/awesome/blob/master/ewmh.c)). `permissions.activate` unminimizes if `hints.raise`, focuses only if `c:isvisible()` (no automatic tag switch), and raises plus sets `c.urgent = true` if hidden ([awesome `permissions/init.lua`](https://github.com/awesomeWM/awesome/blob/master/lib/awful/permissions/init.lua), [awesomeWM/awesome#2](https://github.com/awesomeWM/awesome/pull/2)).
  - *Known bugs:* Custom `request::activate` handlers ignored minimized clients ([awesomeWM/awesome#3329](https://github.com/awesomeWM/awesome/issues/3329)).

- **xmonad:** `EwmhDesktops` routes `_NET_ACTIVE_WINDOW` through `activateHook` (default `doFocus`, switching workspace and focusing; alternative `doAskUrgent`), explicitly ignoring unmanaged/override-redirect windows so popups do not break ([xmonad `EwmhDesktops.hs`](https://github.com/xmonad/xmonad-contrib/blob/master/XMonad/Hooks/EwmhDesktops.hs)).

## 3. Concrete Failure Classes to Pre-empt in Pergola (`x11rb`)

1. **Slow-Subscriber Stall & Missed Startup State:** Synchronous socket writes (`bspwm`'s `fflush` in [`src/subscribe.c`](https://github.com/baskerville/bspwm/blob/master/src/subscribe.c)) block the WM loop if a bar hangs, while bars connecting after startup miss initial state ([bspwm man](https://github.com/baskerville/bspwm/blob/master/doc/bspwm.1.asciidoc)). *Pre-emption:* Use non-blocking sockets with bounded per-subscriber queues and a disconnect timeout (like i3's 10s `kill_timeout` in [`src/ipc.c`](https://github.com/i3/i3/blob/next/src/ipc.c)), plus a snapshot query (`GET_STATE`) or initial-state burst on `SUBSCRIBE`.
2. **EWMH Property Ordering & Transition-Diff Bugs:** Updating `_NET_ACTIVE_WINDOW` before `_NET_CLIENT_LIST` desyncs pagers ([baskerville/bspwm#911](https://github.com/baskerville/bspwm/issues/911)), and emitting events from intermediate mutations produces phantom focus events ([i3/i3#3893](https://github.com/i3/i3/issues/3893)) or missed cross-monitor swaps ([baskerville/bspwm#1166](https://github.com/baskerville/bspwm/issues/1166)). *Pre-emption:* Always update `_NET_CLIENT_LIST` before `_NET_ACTIVE_WINDOW`, and diff committed before/after snapshots to emit bar events.
3. **Focus-Stealing, Unmanaged Popups, & Raise Coupling:** Treating application requests (`data32[0] == 1`) like pager requests (`2`) enables focus stealing ([i3/i3#1426](https://github.com/i3/i3/issues/1426)); activating unmanaged windows breaks override-redirect popups ([xmonad `EwmhDesktops.hs`](https://github.com/xmonad/xmonad-contrib/blob/master/XMonad/Hooks/EwmhDesktops.hs)); coupling focus to raise disrupts floating layouts ([i3/i3#2998](https://github.com/i3/i3/pull/2998)). *Pre-emption:* Gate `_NET_ACTIVE_WINDOW` on `source_indication` (`2` switches workspace/unminimizes/focuses; `1`/`0` marks urgent when off-workspace), drop unmanaged windows, and accept `timestamp == 0` (since pagers/apps commonly send `0`).
